MOS BINARY MANAGER 0.2.2 — PREPARED RELEASE

UPDATE SAFELY
For an existing installation, use MOS's plugin update flow after the release is published. Wait for completion and reload MOS. Do not reinstall over existing settings. This package preparation does not publish or install anything.

EXISTING APPS
Existing IDs, boot flags, arguments and inherited HOME/environment stay unchanged until you enable runtime settings in an app's editor. Nothing moves your old dotfiles or credentials automatically.

PERSISTENT PER-INSTANCE HOME
Open Runtime defaults and choose a storage root inside a real mounted MOS pool. Then Edit an instance, enable runtime settings and choose Managed HOME. Each ID gets <storage-root>/<id>/home. The host checks the mounted storage before creating directories. A missing pool causes a clear failure rather than writing state into RAM. HOME is separate from Working directory.

PATH AND ENVIRONMENT
Add absolute PATH directories one per line. Ordinary environment lines are literal KEY=value; !KEY removes a value and KEY= sets empty. Shared defaults apply only to instances that opt in. No shell expansion or profile sourcing occurs. Ordinary settings are browser-visible: never put secrets there.

SECRETS
Create a protected root-owned 0600/0400 environment file on the host and enter only its path. Its literal KEY=value contents are delivered privately on launch, never added to status or command arguments. Restart the instance after changing the file. Application logs may still print secrets.

DUPLICATE
Duplicate creates a separate named entry with a new ID and managed HOME. It starts disabled, with Start on boot off, and clears the protected-file and explicit XDG references. Review ports, shared-state arguments and credentials before enabling it. Stopping one instance does not intentionally stop another.

APPLY
Applying execution changes restarts only affected instances with Keep running enabled. Stopped instances remain stopped. Name and boot edits do not restart apps. Back up and migrate application data yourself before changing HOME or storage root; no files are moved or deleted automatically.

TEST FIRST
Programs run as root on standard MOS; use trusted foreground programs only. Test harmless loop/failure/clean-exit fixtures, separate HOME and environment values, duplicate isolation, missing-pool behavior, stop, logs and actual reboot. A clean exit stays stopped; errors back off from 1 to 30 seconds. Native arm64 and physical MOS behavior still need host verification.

Full details: docs/INSTANCE-SETTINGS.md and docs/VERIFICATION.md in the source ZIP.
